PRD — Build: Stabilization + Build Story, Project Brain, Coaching & Branding

Task slug: agent-upgrades · Created 2026-07-01 · Companion: progress log · Handoff: docs/agent-upgrades-handoff.md

Summary

Review and land the in-flight working-tree changes (Tailwind pre-bake, Vite prompt switch, install-skip/flicker fixes), remove the highest-risk drift hazards, then extend the Build agent product with three founder-facing capabilities: a non-technical shareable Build Story, a per-project Brain (BRAIN.md) capturing what/why from the user and how/decisions from the agent, and coaching + branding behavior in the agent.

Verified ground truth

  • Live UI is Gleam/Lustre: index.html → src/main.ts → src/main-gleam.ts → src/build_app.gleam with src/build/{model,msg,update,view,effect,runtime}.gleam, actors, components, pure. docs/architecture.md is stale (describes removed React/actors layout).
  • Live TS via externals: src/agent.ts, src/templates.ts, src/projects.ts, src/design-guidance.ts, src/zip.ts, src/publish-files.ts, src/managed-agent-client.ts.
  • Agent protocol: JSON {reply, patches[]}, full-file replacement; 160k-char context budget with ALWAYS_FULL + stubbing, duplicated in src/agent.ts and server/src/prompt.ts (server is source of truth; unification deferred).
  • Starter template duplicated in src/templates.ts and src/build/pure/templates.gleam; no drift detection exists today.
  • SavedProject = {id, name, files, messages, selectedPath, createdAt, updatedAt}; patch history is not persisted — the Build Story requires a new lightweight buildLog going forward and must degrade for old projects.
  • The interview wizard lives inside the starter template's main.tsx; its plan summary becomes the first user chat message (persisted, unstructured).

Definitions (what these mean in Build)

Build Story

Is: a shareable, non-technical narrative of how the app came to be — a view in Build plus an exportable single self-contained HTML file, derived deterministically at render time from chat history + buildLog + BRAIN.md. Is not: a per-turn LLM artifact, a file in the generated project, or telemetry.

Project Brain

Is: a single BRAIN.md at the generated project's root with fixed sections — ## What & Why (seeded from interview; user-owned), ## Brand, ## How it works, ## Decisions (dated log) — maintained by the agent through ordinary patches, riding along in IndexedDB, zip export, and publish for free. Is not: a second database, a transcript, or end-user docs. Hard cap 6,000 chars (prompt rule) with a 10,000-char truncation guard in context selection.

Coaching & Branding

Is: prompt-level behavior — plain-language replies for non-technical founders, one concrete Next: suggestion after substantive changes, and first-build brand proposal (name, palette, tone, logo direction) recorded in BRAIN.md ## Brand and applied in the app. Is not: a separate mode, new UI surface, or logo image generation.

Goals

  1. Eliminate the two drift hazards (template TS↔Gleam, prompt client↔server) with automated tests; fix stale docs; land the flicker/install work safely.
  2. Every project gets a durable, exportable record of what/why and how — BRAIN.md.
  3. A founder can open a Story view and export a polished standalone HTML post — zero setup, zero network calls.
  4. The agent coaches and brands without protocol changes.

Non-goals

  • No accounts, sync, telemetry, or hosted story sharing.
  • No agent JSON schema change; no diff-based patches.
  • No LLM-generated story prose in v1 (deferred D4).
  • No retroactive story reconstruction beyond chat history.
  • No client/server prompt unification this iteration (parity tests are the stopgap).

Constraints (privacy/security first)

  • Anonymous local-first: all new data lives in SavedProject/project files. Exported story HTML is fully self-contained — inline CSS, no external URLs, no fetches.
  • User content in the exported HTML must be HTML-escaped (XSS hard requirement).
  • BRAIN.md joins ALWAYS_FULL in both context selectors; truncation guard above 10k chars keeps the budget safe.
  • Every prompt rule lands in both src/agent.ts and server/src/prompt.ts with parity tests.
  • buildLog entries store truncated prompt/reply + paths only, never file contents. Old projects tolerate buildLog === undefined; no IndexedDB version bump.
  • Small/local models may ignore brain/coaching rules — client-side seeding guarantees the What & Why regardless.

D4 — (Deferred) LLM "polish story" pass

Out of scope for v1.

Taste & originality criteria (Story surfaces)

  • Editorial narrative, not restyled chat bubbles.
  • No generic AI aesthetic (no purple gradients, card grids, default-blue). Single accent drawn from the project's own ## Brand palette when present — each story is tinted by the app it describes.
  • Zero raw file paths / stack jargon / JSON in the default view.
  • Honest: real asks, real changes, real timestamps; no filler hype.
  • Exported HTML looks intentional at 360px and 1200px, prints acceptably, opens offline instantly.
