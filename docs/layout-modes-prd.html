PRD — Journey-based layout modes

Task slug: layout-modes · 2026-07-02 · Branch layout-modes · Companion: progress · Handoff: docs/layout-modes-handoff.md

Definition

A layout mode is ephemeral per-session UI state owned by the Gleam model: which of three fixed arrangements of the two always-mounted surfaces (chat panel, workspace) is visible — ChatMode (full-screen conversational surface), SplitMode (chat ~1/3 + preview ~2/3), BuilderMode (split + files/editor/terminal). UI labels: Chat / App / Code.

Is not: persisted project data (reload deliberately replays chat → reveal); a conditional element tree (all modes render identical DOM, only the .app class changes); a new actor (it generalizes code_panel_open in the preview actor).

Verified ground truth

  • preview_url is never reset — "" only at session boot. Chat-by-default is a session-boot condition.
  • PreviewUrlChanged may NOT re-fire on mid-session remounts (dev server stays alive, webcontainer.ts:80 early-return); crash-restarts DO re-fire. Never rely on URL re-fire mid-session.
  • The interview wizard lives inside the preview iframe — new projects must land in Split so the wizard is visible (the "wizard guarantee").
  • Iframe and .bottom strip must stay mounted across switches (iframe reload flicker; xterm survival via display:none + ResizeObserver refit in terminal.mjs).
  • "Select element" affordance lives in the preview bar (hidden in Chat for free); selected-element panel lives in the chat sidebar (stays usable).

Goals / Non-goals

  • First impression is conversational; boot noise hidden; auto-reveal Split on the session's first preview URL.
  • One segmented control (Chat / App / Code) visible in every mode; auto logic never fights a manual choice.
  • Zero stability regression: no iframe reload, xterm survives, unread badge semantics preserved.
  • Non-goals: floating chat overlay; interview-in-chat; per-project mode persistence; resizable split.

State machine (preview actor)

pub type LayoutMode { ChatMode SplitMode BuilderMode }
State: layout: LayoutMode (replaces code_panel_open), layout_is_manual: Bool
Msg:   LayoutModeSelected(LayoutMode) (replaces CodePanelToggled)
EventRule
LayoutModeSelected(m)Set mode, layout_is_manual = True. Builder clears code_panel_unread. Chat while selecting → disable inspector (BuildInspectorDisable).
PreviewUrlChangedExisting behavior + if ChatMode && !layout_is_manual → SplitMode (the reveal). Re-fires are no-ops.
CodePanelErrorSignaledBadge if not Builder; clear in Builder (port of today's rule).
NewProjectConfirmed / OpenProject / ResetProject (update.gleam)Clear layout_is_manual; if ChatMode && preview_url != "" → SplitMode (wizard guarantee; user-initiated navigation, not a yank). Never move Split/Builder users.

Taste / originality criteria

  • Chat mode reads as a designed conversational product, not a sidebar missing its right half: centered ≤720px column, border removed, generous top spacing, gradient-ringed composer as anchor.
  • Pre-boot chat shows a quiet muted boot status line — no spinner drama; the pulseOrb belongs to the reveal.
  • Chat→Split is the one theatrical moment: a ~200ms restrained transition, no bounce.
  • Segmented control: one capsule, three text labels (no icon-only), active = existing quiet-active convention (#eceef3 + ink), 6px #c2421f unread dot inside Code.

Judge rubric

Standard LFG rubric; taste/originality ≥4 required for the chat surface, segmented control, and the reveal transition. Regression focus: iframe node identity, xterm survival, unread-badge semantics, wizard guarantee.

Risks

  • Stranded Chat mid-session (URL never re-fires) → mitigated by project-open rule; do not rely on URL re-fire.
  • Iframe reload on switch → class-only switching; verify node identity.
  • xterm zero-height fit → existing guard; verify round-trip.
  • Test churn on code_panel tests → port, don't delete.

Definition of done

Steps 1–4 + 6 pass with evidence; Step 5 items verified live where tooling allows, remainder recorded as a manual checklist; suites and build green; judge pass with taste ≥4.
