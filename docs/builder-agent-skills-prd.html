Builder Agent Skills — PRD

Status: Planned

Summary

Improve the Build app's JSON-patching agent (src/agent.ts system prompt) by adding structured skill instructions and expanding the design guidance. The goal is to produce better code with fewer iterations, stronger design, and more reliable self-repair.

Definition

The builder agent is the AI code-generation agent that runs inside each Build project. It receives the project files as context, a user prompt, and returns {"reply": "...", "patches": [...]}. It is not a multi-agent orchestrator — it is a single-shot JSON producer per user message.

"Default skills" in this context means embedding skill-level instructions directly into the agent's system prompt (via JSON_SYSTEM_PROMPT), similar to how design-guidance.ts already injects design instructions. These are not Pi skills — they are prompt-based behavioral guides.

Goals

  1. Stronger design output — The agent currently has a 6-line frontend design note. Expand to match the quality of the standalone frontend-design skill.

  2. Structured planning for complex tasks — Add research-plan-loop style guidance so the agent thinks before writing code, especially for multi-file changes.

  3. Better self-repair — The agent already has a single retry for invalid JSON. Add more robust error recovery patterns.

  4. Cleaner dependency management — The agent needs better guidance on when/how to modify package.json without breaking the WebContainer.

Non-Goals

  • Multi-turn agent loops (the agent still returns one JSON response per message)
  • Adding subagent orchestration inside the build agent
  • Changing the JSON contract or API surface
  • Adding new runtime dependencies
  • Changing the Gleam actors (agent.gleam stays the same)

Constraints

  • System prompt must fit within the context budget (FILE_CONTEXT_CHAR_BUDGET = 160,000 chars). Current prompt is ~1,800 chars.
  • Must preserve existing behavior: JSON-only output, Ollama/OpenRouter support, repair retry, env vars, selected element inspector.
  • Must not change JSON_SYSTEM_PROMPT shape or AgentResult type.
  • Design guidance lives in design-guidance.ts; agent prompt lives in agent.ts.

Proposed Changes

Step 1: Expand frontend-design skill into the system prompt

Acceptance criteria:

  • Replace the current 6-line anthropicFrontendDesignSkill with expanded guidance covering typography, color, motion, spatial composition, and anti-patterns
  • Add guidance about matching complexity to vision (maximalist vs minimalist)
  • Add guidance about avoiding generic AI aesthetics (Inter/Roboto, purple gradients, cookie-cutter layouts)
  • Design guidance is exported from design-guidance.ts as before
  • Agent tests verify the expanded content is included in the system prompt

Step 2: Add research-plan-loop guidance to system prompt

Acceptance criteria:

  • Add a "Planning guidance" section to the system prompt with key principles: understand before changing, plan multi-file changes, start simple, verify each change compiles
  • Include the fast-path vs full-loop triage logic (when to just do it vs when to think first)
  • Keep it under 600 chars to stay within budget
  • Reference the concept explicitly so the agent knows to apply it

Step 3: Improve dependency management guidance

Acceptance criteria:

  • Add explicit rules about Vite version pinning (avoid Vite 8+ due to WASM crashes in WebContainer)
  • Add guidance on using peer-compatible package versions
  • Clarify when to replace package.json vs just adding files

Step 4: Strengthen self-repair guidance

Acceptance criteria:

  • Add guidance about self-verifying changes before returning (type checks, import resolution)
  • Add guidance on how to handle the "I need more context" case (the existing stub response pattern)
  • Clarify that the agent should return {"patches": [], "reply": "need X files"} when it needs more context

Step 5: Add quality checklist

Acceptance criteria:

  • Add a brief pre-return checklist: verify imports resolve, verify no syntax errors, verify the reply is a useful summary, verify patches are complete file contents
  • Keep it to 5-6 bullets, no more than 300 chars

Validation

  • npm test — all existing tests pass
  • New tests for expanded design guidance content in system prompt
  • System prompt length stays under 3,000 chars (well within context budget)
  • No breaking changes to AgentResult or AgentProvider types

Risks

Context bloat: Adding too much guidance could push the system prompt toward the context budget limit. Monitor total prompt size including files. Mitigation: keep each addition tight; the current prompt is only ~1,800 chars with plenty of headroom.
Behavior drift: Adding planning guidance might cause the agent to over-think simple tasks. Mitigation: the fast-path triage (simple one-file changes → just do it) is explicit and short.
