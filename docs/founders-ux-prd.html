PRD — Founder-first UX: interview-in-chat, Focus mode, chat polish

Slug founders-ux · 2026-07-03 · Branch founders-ux · progress · docs/founders-ux-handoff.md · Order: A → C1/C2 → B → C3; cut line if time-boxed: A + C ship, B follows.

Definitions

Interview-in-chat is the 7-question onboarding conversation rendered natively in the chat panel's messages scroller, answered through the existing composer, producing the byte-identical plan summary msg.BuildFromPlan already consumes. It is not a form transplanted into bubbles (no progress bar, no "Question 3 of 7", no review grid), not AI-driven (canonical constant questions), not persisted state, not a second chat surface.

Focus mode is a fourth LayoutMode: full-bleed preview with the same .panel.chat node restyled by CSS into a docked bottom-right companion card. It is not a second chat node, not draggable/resizable, not a modal, never auto-entered, not persisted.

Goals / Non-goals

  • Chat mode is the true front door — a new founder never needs the iframe to start.
  • Plan-summary format, BuildFromPlan handling, BRAIN.md seeding, Build Story derivation byte-for-byte unchanged downstream.
  • Invariants hold: identical DOM (iframe + xterm never remount), chat during boot, no yanks, drift test green.
  • Non-goals: resizable split; persisted layout; interview branching/AI questions; persisted mid-interview answers; migrating legacy project files; Focus drag/collapse.

A — Interview-in-chat

Actor (new src/build/actors/interview.gleam)

Stage = Idle | Asking(index: Int) | Reviewing
State(stage, answers: List(String))   // "" = skipped
Msgs: InterviewStarted, AnswerSubmitted(String), QuestionSkipped, InterviewDismissed, InterviewCompleted

Holds the canonical 7 questions (idea/audience/problem/features/data/style/integrations: key, label, helper, placeholder) and plan_summary(answers) replicating the wizard's compact() fallbacks and exact output format — the single source of truth once the wizard is deleted; a golden test pins the legacy strings.

Rendering: virtual bubbles (key decision)

Q&A render from interview state into the same .messages scroller (assistant-styled questions, user-styled answer echoes) but are never appended to chat.messages. Build fires the existing BuildFromPlan, which appends the standard plan message. Wins: Build Story derivation untouched (no junk chapters from Q→A pairing), persistence/agent-context shapes untouched, reload semantics free. Composer placeholder becomes the current question's placeholder; submit routes to the interview.

Lifecycle

Eligibility (evaluated at project-navigation events only): chat.messages == [] && project.build_log == [] — Clear-chat can never re-trigger; any ever-built project is excluded.

EventRule
ProjectReady at booteligible → Asking(0)
NewProjectConfirmed / ResetProject→ Asking(0)
OpenProject dispatchedDiscard in-flight answers immediately (→ Idle, answers cleared) — a mid-interview switch must never seed another project's plan with stale answers.
MessagesReplaced after a project loadsRe-evaluate eligibility against the loaded project: empty messages ∧ empty build_log → fresh Asking(0); otherwise Idle. (Load order is ProjectLoaded → MessagesReplaced, so build_log is hydrated when this fires.)
ChatClearedno change
Composer submit while Asking(i)record answer; advance; i==6 → Reviewing. Not gated on remounting or budget — the interview touches no container or model.
Skip (ghost, current question) / "Just describe it instead" (first question only)record ""; advance / → Idle
Build button in Reviewingdispatch BuildFromPlan(plan_summary(answers)); the interview idles only on successful dispatch (agent actually started). If the dispatch is gated — agent running, remounting, or BYOK settings missing (which auto-opens the settings modal) — the interview stays in Reviewing with all answers intact, and the interview-end reveal does not fire. Test: gated_build_keeps_reviewing.
Any agent-bound SubmitPrompt, ImproveSelectedElement, or successfully-dispatched BuildFromPlan (incl. legacy iframe postMessage)→ Idle (defensive; a gated/no-op dispatch never idles — see Build row)
Empty composer submit while AskingNo-op — Enter-happy founders must not skip questions silently; Skip is the explicit affordance.

Reload mid-interview: session-only, restart from Q1 (virtual bubbles aren't persisted; predicate re-fires). A saved project with messages structurally cannot re-interview. Known acceptable edge: a legacy never-built project still carries the old iframe wizard in its files — if the user manually reveals the preview mid-interview, both onboarding surfaces are visible; the suppressed reveal plus the defensive idle on the wizard's postMessage keep them from conflicting.

Layout-journey changes (intentional inversions of shipped rules)

  1. Auto-reveal suppressed while interviewing: URL during stage != Idle goes through new pure preview.record_url (stores URL, no reveal, preserves the inspector re-enable side effect). The reveal moves to interview end (BuildFromPlan or dismissal): if ChatMode ∧ !manual ∧ url≠"" → Split via preview.reveal. The moment now lands when the agent starts building — a better beat than "vite booted".
  2. on_project_navigation no longer moves ChatMode→Split (the wizard-visibility rationale is gone). Still re-arms layout_is_manual = False. Two layout tests invert with explanatory comments; architecture.md updated.

Template swap + compat

Wizard main.tsx → welcoming placeholder in both copies, byte-identical (keeps ./build-inspector + ./style.css imports, "Welcome to Build." voice, one calm line). Keep the BUILD_APP_FROM_PLAN postMessage route (legacy local projects embed the old wizard forever; the handler is the interview's completion path and now also idles the interview). templates.test.ts assertions updated; fallback-string assertions move to interview tests.

Interview taste criteria

  • Talking, not form-filling: one assistant bubble per question (label + quieter helper line inside the bubble); composer placeholder carries the example; no counters or progress chrome.
  • Recap is a message ("Here's what I heard — …") + primary "Build my app" + ghost "Start over"; no editable grid.
  • Answers echo as the founder's own user-styled bubbles; each question auto-scrolls; composer keeps focus.

B — Focus mode

  • FocusMode variant; control order Chat / App / Focus / Code; manual entry only; never auto-entered; navigation never moves Focus users; unread-dot semantics unchanged; element selection stays armed (only ChatMode disarms).
  • CSS only: .app.modeFocus → single-column grid; the same .panel.chat becomes position:fixed bottom-right card (≈380px, max-height ≈62vh, house tokens, 240ms rise-in). Header description, bootStatus, projectControls hidden in Focus; titleRow stays (it holds the only exit). While selecting an element: card fades to .25 opacity + pointer-events:none (explicit class from view) so clicks pass through; restores on selection.
  • Modals-in-Focus rule (required): all four modals and the element picker render inside .panel.chat, and position:fixed resolves against any transformed ancestor — so the Focus card must have no resting or animating transform/filter on .panel.chat itself (the enter animation uses opacity only, or animates an inner wrapper), keeping .modalBackdrop full-viewport. The selection-ghosting class (opacity:.25; pointer-events:none) must not apply while a modal is open. Step 9 acceptance includes: open the settings modal in Focus → full-viewport interactive overlay (smoke-asserted). Note the settings modal IS reachable in Focus (missing-BYOK auto-open) even with projectControls hidden.
  • Taste: companion, not popup ad — house material, never pulses; messages naturally clamp to the last few bubbles; composer keeps the gradient ring.

C — Chat polish

  1. Empty-state void: center the lone .empty suggestion vertically in ChatMode (:has selector); composer stays pinned.
  2. Export/Reset icons move from .actions to the .chatTools row; actions become Send/Cancel only.
  3. Roving focus on the segmented control (after B: 4 segments): active segment tabindex 0, others −1; ArrowLeft/Right select-follows-focus; stop at ends; FocusLayoutSegment effect refocuses after re-render.

Judge rubric

Standard LFG rubric. Taste/originality ≥4 required for: the interview conversation (talking, not form-filling), the recap moment, the relocated reveal beat, and the Focus card (companion, not popup ad). Regression focus: drift test, iframe/xterm identity, plan-summary byte-parity, no-yank rules, legacy BUILD_APP_FROM_PLAN compat.

Risks

  • Intentional test/smoke inversions must not read as regressions — each flipped assertion carries a comment naming the interview.
  • Drift-test trap on the template swap — single step, validated only via npm test.
  • Reveal edges: dismissal-before-URL must re-arm the URL-arrival reveal.
  • Legacy wizard postMessage race — handler idles the interview defensively.
  • Focus fixed-position card over live iframe + pointer-events pass-through — verify with the real inspector in smoke.

Definition of done

Steps 1–8 pass with evidence (A + C1/C2); steps 9–10 (B + C3) pass or are explicitly handed off as the follow-up per the cut line; suites/build/smokes green; judge pass with taste ≥4 on the named surfaces.
