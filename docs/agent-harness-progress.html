Progress — agent-harness

Overall status: release 1 complete — All twelve units done, BYOK tool mode in, and validated against a real model. PRD: agent-harness-prd.html · handoff: agent-harness-handoff.md · branch agent-harness (27 commits off 8c9b385)

The single-shot {reply, patches[]} protocol is gone: agent.Patch, AgentRequestSucceeded, apply_patches, and InstallIfNeeded(patches) are all removed. One write path, one install trigger. Boundary attestations

The invariants that can silently rot. Each is pinned by a test or a grep, not by a comment.

  • held No fs_*/exec tool is gated — asserted in agent-tools.test.ts ("names no gated tool") and in prompt-parity.test.ts ("marks no client tool as approval-gated"). Deny list (.env, *.pem, node_modules/, …) covered by 20 path-policy cases.
  • held No web tool leaks into BYOK — prompt-parity.test.ts "never names a web tool in the client tool surface"; agent-step.test.ts "never offers a web tool"; runTool refuses web_fetch/web_search/web_post by name.
  • held Ollama is never offered tools — enforced by the literal type LLMStepParams.provider: 'openrouter' plus a @ts-expect-error test and a runtime assertion that the JSON path still forces format: 'json'.
  • held bootGate awaited on every new container path — spawnAgentCommand and flushContainerWrites both await it before touching the container.
  • held No direct wc.fs.writeFile outside src/webcontainer.ts — grep across src/; agent-tools.ts mentions it only in the comment explaining why it must not call it.
  • held No agent tool can publish — CLIENT_TOOL_SPECS is exactly [fs_list, fs_read, fs_write, fs_batch_write, exec], asserted; runTool refuses everything else.
  • held Constants cannot drift — MAX_CALLS_PER_STEP and MAX_TOOL_STEPS compared across agent.gleam, server/src/agent-tools.ts, and server/src/step-token.ts.
  • held Turn state empties on every terminal transition — abortAgent clears both maps, and the harness smoke asserts pendingTurnCount() === 0 after a cancel. ResetProject now routes through AgentRequestCanceled (blocker B7), with a test that a late AgentStepReturned for the canceled turn is inert.
  • held Exactly one install trigger — InstallDependencies is the only one; InstallIfNeeded(patches) and apply_patches are removed, verified by grep.

The bug the live run found — and nothing else could

The user's request was dropped after step 0. userPrompt was sent only when stepIndex === 0, so from step 1 the model had tool results and no request. It read files, found nothing to act on, and replied "Looks like you sent a blank message — what would you like to create?". The turn completed successfully with zero files changed, so nothing in the harness registered a failure. Present in both transports.

500+ tests and three stubbed smokes missed it because a stub does not care what you ask it. This is the entire argument for a live run as the acceptance gate rather than a formality. Bugs found while building (not pre-existing)

  • The agent was blind to the project (found by driving the trail in a real browser). publishProjectFiles fired only from SaveCurrentProject/ScheduleSave, and autosave is gated on the container being hydrated — so on a fresh boot the snapshot was empty and fs_list returned "The project has no files." The agent would have rewritten files it could not read. Fixed at three levels: seeded in setLastFiles (boot/remount is the only path carrying files on a first run), seeded on Loaded/Created/FilesUpdated, and upserted on every WriteFileToContainer. The smoke now asserts a non-empty snapshot.
  • Three runtime-only reference errors that vitest never executes: dispatchAgentSucceeded still referenced the removed AgentRequestSucceeded/Patch constructors, and agent.mjs used dispatchAgentStepReturned and dispatchAgentTimeoutReached without importing them — so the turn deadline would have thrown instead of ending the turn.
  • exec concurrency race. The slot was claimed only after await ctx.spawn(...), so two calls in one step could both pass the guard and race two installs against node_modules. Now claimed synchronously, with a deferred kill so an abort landing mid-spawn is still honored. Surfaced by writing the concurrency test.
  • validateExec rule ordering. The metacharacter sweep ran before the node -e rule, so node -e 'console.log(1)' was refused with the generic "contains shell characters" instead of the one that tells the model what to do instead. A refusal that does not teach invites a retry.
  • flushContainerWrites data loss. First implementation cleared debounced editor writes instead of performing them — it would have silently dropped the user's in-flight keystrokes whenever the agent ran a command. Now the pending payload is tracked alongside the timer and written out.

  • Two more bugs the end-to-end smoke caught in U12, both the same class as the blind-agent bug: FileRemoved was missing from update.gleam's auto-save branch, and the snapshot removal sat after await bootGate so a delete during boot would leave the file visible to fs_list forever. The agent's file snapshot must never depend on an async path settling.
  • BYOK validated live; managed mode is not. The live run went through the BYOK transport (a real OpenRouter key, no Clerk).   • S2 still needs a corpus. S1 is observed at 4/4 across the single-turn and suite runs, and S4 has real numbers (5–11 steps, 5–10 provider calls per turn), but the broken-handback rate needs a population, not four turns.
  • Step counts vary run to run — the same multi-file prompt took 6 steps once and 11 another. Well inside the budget, but it means p50 needs more samples than this.
  • Two more bugs found by driving BYOK against a stubbed provider. Agent workspace — first slice (personas)

One file: .build/agents/hyper/user.md, global scope, injected at the top of every turn ahead of the skills manifest. It carries the things a user would otherwise retype — "I use Tailwind", "keep copy lowercase".

The design point is the asymmetry. A persona is injected as trusted guidance; the skills manifest, three feet away in the same prompt, is injected as untrusted data. That is defensible for exactly one reason: the agent cannot write a persona. .build/agents/** is refused by fs_write, fs_batch_write and fs_delete while staying open to fs_read. A skill file is agent-writable, which is why a prompt injection reaching one tool call could plant one and have it re-read with authority every turn afterwards — a one-shot compromise made durable. If that write ban is ever lifted, the trusted framing must go with it; the two facts move together and there are tests on both halves.

The bug the persona run found: verification was never running

Seeding a persona was incidental to the real find. The new refusal log surfaced exec: [exit 1] followed by tsc's help text — and reproducing it outside the browser was decisive:

  • The starter template shipped no tsconfig.json. With no config and no file arguments, tsc does not typecheck at all: it prints its usage banner and exits 1. npx tsc --noEmit is the headline command of the built-in verify skill, so every turn that tried to verify burned a step on a command that could not succeed.
  • It also shipped no @types/react / @types/react-dom, so even with a config a real error drowns under TS7016/TS7026 noise about React having no declarations.
  • typescript: "latest" had silently resolved to TypeScript 7.0.2, the native rewrite — a major version change under existing projects, in the one dependency this template left unpinned while carefully pinning everything else.

Fixed on both duplicated template surfaces (the drift guard caught the Gleam side, as designed): a tsconfig.json with types: ["vite/client"] so side-effect CSS imports are not reported as TS2882, React type declarations, and typescript pinned to ^5.7.2. tsconfig.json joins UNDELETABLE — deleting it does not break the app, it breaks the agent's ability to check the app, which is worse because the loop keeps reporting that it verified.

The editor was then verified in a real browser against nine conditions — visible on first run, enables on edit, disables after save, the agent reads exactly what was typed, it reaches the prompt framed as guidance, the agent still cannot overwrite it, it survives reload, and clearing the box removes the file rather than leaving an empty one. The reload check failed first time and found a real bug: the panel starts open, so no SettingsOpened message is ever sent on a fresh load and the load effect never fired — standing instructions would have looked lost on every reload.
