Boundary attestations

The invariants that can silently rot. Each is pinned by a test or a grep, not by a comment.

  • held No fs_*/exec tool is gated — asserted in agent-tools.test.ts ("names no gated tool") and in prompt-parity.test.ts ("marks no client tool as approval-gated"). Deny list (.env, *.pem, node_modules/, …) covered by 20 path-policy cases.
  • held No web tool leaks into BYOK — prompt-parity.test.ts "never names a web tool in the client tool surface"; agent-step.test.ts "never offers a web tool"; runTool refuses web_fetch/web_search/web_post by name.
  • held Ollama is never offered tools — enforced by the literal type LLMStepParams.provider: 'openrouter' plus a @ts-expect-error test and a runtime assertion that the JSON path still forces format: 'json'.
  • held bootGate awaited on every new container path — spawnAgentCommand and flushContainerWrites both await it before touching the container.
  • held No direct wc.fs.writeFile outside src/webcontainer.ts — grep across src/; agent-tools.ts mentions it only in the comment explaining why it must not call it.
  • held No agent tool can publish — CLIENT_TOOL_SPECS is exactly [fs_list, fs_read, fs_write, fs_batch_write, exec], asserted; runTool refuses everything else.
  • held Constants cannot drift — MAX_CALLS_PER_STEP and MAX_TOOL_STEPS compared across agent.gleam, server/src/agent-tools.ts, and server/src/step-token.ts.
  • held Turn state empties on every terminal transition — abortAgent clears both maps, and the harness smoke asserts pendingTurnCount() === 0 after a cancel. ResetProject now routes through AgentRequestCanceled (blocker B7), with a test that a late AgentStepReturned for the canceled turn is inert.
  • held Exactly one install trigger — InstallDependencies is the only one; InstallIfNeeded(patches) and apply_patches are removed, verified by grep.
  • held Exactly one write path — project.FileApplied. The harness smoke proves a written file is immediately visible to the agent's own fs_list/fs_read (S5).

Bugs found while building (not pre-existing)

  • The agent was blind to the project (found by driving the trail in a real browser). publishProjectFiles fired only from SaveCurrentProject/ScheduleSave, and autosave is gated on the container being hydrated — so on a fresh boot the snapshot was empty and fs_list returned "The project has no files." The agent would have rewritten files it could not read. Fixed at three levels: seeded in setLastFiles (boot/remount is the only path carrying files on a first run), seeded on Loaded/Created/FilesUpdated, and upserted on every WriteFileToContainer. The smoke now asserts a non-empty snapshot.
  • Three runtime-only reference errors that vitest never executes: dispatchAgentSucceeded still referenced the removed AgentRequestSucceeded/Patch constructors, and agent.mjs used dispatchAgentStepReturned and dispatchAgentTimeoutReached without importing them — so the turn deadline would have thrown instead of ending the turn.
  • exec concurrency race. The slot was claimed only after await ctx.spawn(...), so two calls in one step could both pass the guard and race two installs against node_modules. Now claimed synchronously, with a deferred kill so an abort landing mid-spawn is still honored. Surfaced by writing the concurrency test.
  • validateExec rule ordering. The metacharacter sweep ran before the node -e rule, so node -e 'console.log(1)' was refused with the generic "contains shell characters" instead of the one that tells the model what to do instead. A refusal that does not teach invites a retry.
  • flushContainerWrites data loss. First implementation cleared debounced editor writes instead of performing them — it would have silently dropped the user's in-flight keystrokes whenever the agent ran a command. Now the pending payload is tracked alongside the timer and written out.

Residual risks

  • No live-model run yet. The loop is exercised end-to-end by the harness smoke with the real executors, real project state, and the real actor — but the step responses are injected rather than returned by a provider. A managed run against a real OpenRouter key is the remaining validation, and it is what S1/S2/S4 need before they can be measured.
  • BYOK-OpenRouter is still on the single-shot JSON path. The tool transport exists on the client (FetchLLMClient.step, tested), but runStep only drives the loop in managed mode; BYOK falls through to runAgent. Patches still land through FileApplied, so nothing is broken — BYOK simply does not get tools yet.
  • A6 — dev-server restart cadence, partially mitigated. webcontainer.ts notes that container writes do not reliably trigger vite's watcher, so the dev server exits and auto-restarts after 1s. Today a turn writes once; under the loop it writes in bursts. flushWrites before exec is in place, but suppressing preview-error capture while the agent runs belongs to U7a. Until then, a multi-step turn could flood [preview error] lines and pop the Try-to-fix card mid-work — which would make S2 worse from cadence alone.
  • R1 injection→exec chain is not yet live and will not be until U11 adds web tools. Shipping U1–U9 without web tools keeps that entire surface out of release 1 — the reason the plan gate recommended deferring it.
  • R2 — .env deviation. Denied rather than approval-gated, because the mechanism the locked decision would gate does not exist (no env channel in the Gleam effects or the request body). Strictly stronger than gating; recorded as a mechanism deviation, not a scope change.
  • The npx boundary is reliability, not security. Narrowed to {tsc, vite} so it no longer defeats the node -e denial beside it, but npm install still runs postinstall scripts and the container still has open egress. Recorded in the source, not just here.
  • A1 unproven — the Render Node runtime's tolerance of a custom dns.lookup (needed for anti-DNS-rebinding) is still an assumption; it only becomes load-bearing at U11.
  • The tool specs are a new duplicated surface (client executes / server declares). Guarded by prompt-parity.test.ts, and the guard was verified to bite — but it is a third pair to keep honest alongside the prompt and the starter template.
  • Server typecheck excludes test files (tsconfig.json exclude), so a fake that drifts from an interface — e.g. a Db stub missing updateModel — is caught only at runtime. Two fakes needed manual updating this loop for exactly that reason.
